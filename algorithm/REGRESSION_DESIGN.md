# 二元逻辑回归分析开发文档

## 1. 目标与范围

在现有 `algorithm` 包中增加一个独立的回归分析模块，用于评估两个临床参数对心脏病阳性结果的关联，并验证模型的拟合优度和预测表现。

本期只实现二元 Logistic 回归，不修改现有工作台的描述性统计口径，也不在首页加载时自动拟合模型。

### 本期分析方案

- 因变量：`y = (target > 0)`，阳性记为 1，阴性记为 0。
- 自变量：从可用字段中选择任意两个，由配置传入。当前默认示例为：
  - `cp`：胸痛类型；
  - `oldpeak`：ST 段压低，单位为 mm。
- 模型：带截距的二元 Logistic 回归。
- 默认选择这两个参数的原因：`cp` 是与结局相关的分类变量，`oldpeak` 是关联较强的连续变量，两者组合在当前数据上的 5 折交叉验证 ROC-AUC 高于 `age + oldpeak`。实际运行时允许替换为任意两个符合字段契约的自变量。
- 结论边界：结果用于关联分析和模型可行性评估，不作因果推断，也不作为临床诊断依据。

## 2. 数据与输入契约

数据通过现有 `load_dataset()` 加载，沿用 [`schema.py`](./schema.py) 和 [`dataset.py`](./dataset.py) 的字段校验。

当前数据集规模为 303 例，其中阳性 139 例、阴性 164 例。默认组合中的 `cp` 和 `oldpeak` 均无缺失，因此可使用全部 303 例样本。若更换自变量或替换数据产生缺失，应由回归模块显式报告有效样本数，禁止静默填充或丢弃记录。

建议的输入检查：

1. `target` 只能取 0–4，并转换为 `target > 0`；
2. 两个配置自变量必须存在且可转换为数值或分类编码；
3. 有效样本数必须大于 0，且同时包含 0 和 1 两个结局类别；
4. 记录实际使用样本数、阳性数、阴性数和数据指纹。

## 3. 数学定义

以下以默认的 `cp + oldpeak` 组合说明。若更换自变量，只需替换 `x1`、`x2` 及对应的编码和单位信息。

令：

```text
x1 = cp
x2 = oldpeak
y  = 1(target > 0)
```

模型为：

```text
logit(P(y=1)) = β0 + β1*x1 + β2*x2
P(y=1) = 1 / (1 + exp(-(β0 + β1*x1 + β2*x2)))
```

主要解释量为优势比（odds ratio）：

```text
OR_cp      = exp(β1)
OR_oldpeak = exp(β2)
```

解释时应明确“其他变量保持不变时，自变量每增加 1 个单位，阳性优势比如何变化”。同时报告 95% 置信区间和 p 值。

## 4. 模块与接口设计

建议新增以下文件：

```text
algorithm/
├── regression.py              # 拟合、预测、评估
├── regression_models.py       # 回归结果 dataclass
└── tests/test_regression.py   # 回归模块测试
```

推荐接口：

```python
from algorithm.regression import run_logistic_regression

result = run_logistic_regression(dataset)
```

推荐的结果对象至少包含：

```python
RegressionResult(
    outcome="target_positive",
    predictors=tuple[str, str],
    n=303,
    positive=139,
    negative=164,
    coefficients=tuple[CoefficientStat, ...],
    fit=FitStat(...),
    validation=ValidationStat(...),
    dataset_fingerprint=str,
    algorithm_version=str,
)
```

其中：

- `CoefficientStat`：变量名、系数、标准误、OR、OR 的 95% CI、p 值；
- `FitStat`：log-likelihood、deviance、LR 统计量、LR p 值、AIC、BIC、McFadden pseudo-R²；
- `ValidationStat`：ROC-AUC、PR-AUC、Brier score、校准截距、校准斜率，以及交叉验证结果。

回归接口应接收 `Dataset`，但不应被 `build_workbench()` 默认调用。这样可以保持首页构建链路稳定，并允许后续在单独分析页面或报告生成流程中调用。

## 5. 拟合与预处理流程

### 5.1 建模流程

1. 读取并校验 `Dataset`；
2. 校验配置中的两个自变量均存在，且不能重复或等于 `target`；
3. 构造 `y = target > 0`；
4. 取配置指定的两个自变量，检查缺失和有限值，并按字段类型完成编码；
5. 拟合带截距的 Logistic 回归；
6. 计算系数、OR、置信区间和显著性；
7. 计算拟合优度指标；
8. 使用分层交叉验证评估预测性能；
9. 生成结构化结果对象。

### 5.2 连续变量检查

Logistic 回归要求连续变量与 logit 之间近似线性。第一版应至少提供检查结果：

- 两个所选自变量的取值范围和分布；
- 分箱后的阳性率趋势；
- 线性项与简单非线性项的对比，作为诊断而不是自动改模。

如果线性假设明显不成立，后续再考虑限制性立方样条或分段项，本期不自动增加复杂度。

## 6. 评估指标

### 6.1 拟合优度

拟合优度是本期核心评估目标，至少输出：

1. **对数似然（Log-Likelihood）**：衡量模型对观测结果的解释程度；
2. **偏差（Deviance）**：用于比较不同模型；
3. **似然比检验（Likelihood-Ratio Test）**：比较二参数模型与仅含截距的空模型；
4. **AIC、BIC**：比较模型拟合与复杂度；
5. **McFadden pseudo-R²**：描述相对空模型的改进程度；
6. **Hosmer–Lemeshow 检验**：仅作为辅助，不作为唯一通过标准。

不能仅依据 Hosmer–Lemeshow 的 `p > 0.05` 判断模型良好，因为该检验受分组方式和样本量影响较大。

### 6.2 校准能力

预测概率是否可信，需要报告：

- 校准曲线；
- 校准截距，理想值接近 0；
- 校准斜率，理想值接近 1；
- Brier score，越低越好。

### 6.3 区分能力

报告：

- ROC-AUC；
- PR-AUC；
- 选定阈值下的敏感度、特异度、阳性预测值和阴性预测值。

由于阳性率约为 45.9%，不能只报告 ROC-AUC，应同时保留 PR-AUC。

### 6.4 稳定性

采用 5 折分层交叉验证，并报告各指标的均值和标准差。数据量较小，不建议切出固定测试集后再据此做强结论。最终报告可增加 Bootstrap 置信区间。

## 7. 验收标准

### 功能验收

- 能从默认 Cleveland CSV 成功拟合模型；
- 结果中明确记录 `n=303`、阳性数和阴性数；
- 两个自变量的系数、OR、95% CI 和 p 值均可读取；
- 能输出 LR 检验、AIC、BIC、pseudo-R²、ROC-AUC、PR-AUC、Brier score；
- 能输出校准截距、校准斜率和交叉验证摘要；
- 数据缺失、单一类别、非法值时抛出明确的领域异常。

### 质量验收

- 回归模块不引入 Qt/PySide 依赖；
- 不改变现有 `WorkbenchPayload` 的字段和数值；
- 同一数据指纹和配置下结果可复现；
- 测试覆盖正常数据、缺失值、单一结局类别和小样本边界；
- 所有显示数值继续使用项目现有的确定性舍入策略。

## 8. 依赖建议

若需要标准误、置信区间、p 值和拟合优度，建议使用 `statsmodels`。若需要交叉验证、ROC/PR、校准和 Brier score，建议使用 `scikit-learn`。

为避免影响主程序启动，建议将回归依赖作为可选分析依赖，或在首次进入回归分析功能时检查依赖并给出明确提示。若项目必须保持最小依赖，则可先实现预测和基础指标，但不建议自行重复实现完整的统计推断流程。

## 9. 后续扩展顺序

1. 增加 `cp`、`thal`、`ca` 等变量，形成多变量解释模型；
2. 比较 `age + oldpeak` 与扩展模型的 AIC、BIC、校准和交叉验证表现；
3. 对 `target` 的 0–4 等级尝试有序 Logistic 回归；
4. 仅在有明确假设时加入性别×胸痛类型等交互项；
5. 若样本量扩大，再评估惩罚回归或更复杂的预测模型。

本期不建议直接使用普通线性回归拟合 `target=0..4`，也不建议把模型结果解释为因果关系或临床诊断结论。

## 10. 多元 Logistic 回归模式

当前 UI 已提供模型模式选择，算法层按变量数量自动选择模型：

- 选择 2 个参数：调用当前二变量 Logistic 回归流程；
- 选择超过 2 个参数：调用多元 Logistic 回归流程；当前页面提供 4 个参数选择框；
- 选择少于 2 个参数：提示参数数量不足，不执行本分析。

算法接口接收 `predictors` 序列，并将“变量数量到模型类型”的判断放在分析服务层，而不是放在 Qt 页面代码中。多元模型复用当前的编码、缺失处理、拟合优度、校准和交叉验证流程，并额外增加参数数量与事件数的检查，避免在 303 例数据上放入过多变量导致过拟合。
